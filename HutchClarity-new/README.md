## Problem statement
Prepaid customers lose money and nobody can say why: reloads taken twice, surprise VAS debits, "unlimited" data that stops at a hidden fair-use cap, and support that doesn't resolve. The evidence exists, but it is split across payment, charging, catalogue, consent and usage systems. See [enterprise-plan/01](enterprise-plan/01-executive-summary-problem.md).

## Solution overview
One platform for customers (web, Hutch app, WhatsApp, SMS/USSD) and staff (Clarity Desk) that:
- **explains** any charge with evidence and ruled-out causes,
- **fixes** known causes by deterministic, versioned rules (auto, one tap, or staff approval),
- **proves** every fix with a signed, QR-verifiable Trust Receipt,
- **prevents** repeats with safeguards, Complaint Autopsy and Foresight.

**Rules decide. The LLM explains.**

## Key features
Why? button with evidence · one-tap fixes · zero-contact refunds · Trust Receipts · proactive bill-shock and fair-use alerts · Clarity Desk (queue, cockpit, approvals, teach once, policy what-if) · Policy Studio for safe policy changes · Complaint Autopsy · Foresight-lite · MCP server for HUTCH's AI agents · si/ta/en throughout. Feature map: [enterprise-plan/17 §3.1](enterprise-plan/17-build-blueprint.md).

## Technology stack
Python 3.14 · FastAPI · PostgreSQL 18 + pgvector · Valkey · Apache Kafka · Keycloak · OPA · GoRules ZEN · OpenTelemetry · Next.js 16 · TypeScript · Tailwind/shadcn · MCP · Gemini + Groq (prototype LLMs, by role). Full stack and rationale: [enterprise-plan/18](enterprise-plan/18-tech-stack-and-ai.md).

## Architecture overview
Modular monolith with separately deployed services, layered L0–L7, every HUTCH system behind a port and simulated by `hutch-sim`. See [ARCHITECTURE.md](ARCHITECTURE.md) and [enterprise-plan/17](enterprise-plan/17-build-blueprint.md).

## Setup / installation *(after build)*
Daily development needs only Python, Node and PostgreSQL (`lite` profile: `make dev`). The full infrastructure runs with `make up-full`. Details will be in walkthrough WT-01.

## API / external service requirements
