## What changed
- CORS is the outermost middleware, then the security headers, then the rate limiter.
- A 429 now carries `Access-Control-Allow-Origin` for an allowed browser origin.
- Regression test: `test_a_refused_call_still_tells_the_browser_which_origin`.

## Why
Sign-in showed "Failed to fetch". The API was refusing the call as too many requests, and that response skipped CORS, so the browser hid the real reason.

## Decisions made
Middleware is registered from the route outward because Starlette runs the last one added first. The previous comments described the opposite order.
